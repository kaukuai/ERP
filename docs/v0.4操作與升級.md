# v0.4 操作與升級

v0.4 將原有 20 項「待建置」需求接成可操作的軟體流程。18 項在清單所列範圍內可操作；E08 當期官方發票交換規格與 X10 完整 POS 的實機／金流／發票整合仍為部分具備。另完成 B10 逐次／月結立帳政策。

這不是全功能對等或正式上線宣告。完整清單仍有 31 項部分具備、14 項需外部整合，不能把「待建置 0」解讀為全部完成。

本文件記錄 v0.4 原始流程；v0.4.1 的部署與 Excel 映射、schema 12 升級請另見 [更新與部署](v0.4.1更新與部署.md)。

## 多公司帳套

主要帳套的代碼固定為 `default`。建立公司時填名稱、小寫英數連字號代碼、獨立管理員帳密與預設倉庫。密碼只在應用程式的建立／登入表單輸入，不貼入聊天或環境腳本。

每家公司使用主資料庫同層 `.company-workspaces/` 中的獨立 SQLite，目錄與檔名由伺服器產生，使用者不能指定任意檔案路徑。各公司的原始帳套資料不互相複製，不共用 Session 或 CSRF。列印連結帶明確公司代碼。

要看分公司彙總，先登入該公司，以其管理員授權主要帳套帳號；再回主要帳套查閱。可以只開營收／應收付，不開成本。授權可撤銷，不授予來源公司的登入、明細或修改權。彙總沒有內部交易抵銷，不是法定合併財報。

## 月結與原有帳務

每次出入庫凍結當下政策。既有逐次立帳不會因主檔改成批次而回改；已記待立帳的交易也不會因改回逐次而消失。

批次應收先列 `1110 待立帳應收`，批次應付先列 `2005 待立帳應付`。截止後月結轉入 `1100 應收`／`2000 應付`；不再次認列營收、存貨或費用。月結前的退貨回沖待立帳科目，月結後按原帳款及待退款處理。帳齡只列已立帳交易。

月結帳單保留每筆來源快照；後續退貨、折讓、收付更新可查的目前餘額，原快照不覆寫。主表以月結帳單呈現，原來源仍可供預收抵付及票據等流程核對。

## 檔案匯入

訂單匯入使用 UTF-8 CSV。範本的來源系統／商店代碼須與 SKU 映射一致。同一外部單號的客戶、倉庫、日期、稅別與備註須一致；同商品需先合併為相同交易單位的一列。錯誤批次不建立訂單。

銀行對帳使用 XLSX 第一張工作表或 UTF-8 CSV，第一列為唯一且非空欄名，最多 2,000 筆、60 欄；畫面上傳限 1 MB。XLSX 僅純值，不支援 `.xls`、巨集、公式、外部實體或損壞 ZIP。Excel 日期序號可轉成日期。正數為收款，負數為付款。原交易編號必須穩定；找不到對象或不能完整配對時人工核對，不能以猜測直接過帳。先於立帳的收款應走預收付流程。

發票交換只保存外部既有紀錄及其參考憑據，不會連線開立或宣告驗證正式回執。所需的當期官方與加值中心格式仍列 E08 差距。

## POS 設定與使用

先在「資金與票據」建立現金／銀行帳戶，在「門市 POS」建立或修改門市設定。每個門市指定扣庫倉、零售客戶與允許收銀的帳號；管理員／主管可管理門市，業務須逐店授權。

開班填實際盤點現金；它是盤點紀錄，不會假造銀行期初分錄。鍵盤式掃碼器可輸入商品或交易單位條碼並按 Enter 加入；也可手動選品。售價、促銷與點數由伺服器重算，不能由用戶端傳入任意價錢。每列擇最優惠促銷、不疊加；點數是按未稅價計的促銷折抵，不可換現。

預覽後填現金／銀行／外部終端的實收分配。分配合計須等於應收，現金實收可大於分配以找零。外部終端必須先取得實際成功結果再登錄參考號；設定設備名稱不會自動連接金流。零售即時收款不受該零售客戶的月結政策延後，但不修改其一般交易政策。

退貨須由 POS 流程處理，同步原出貨、實際退款、點數及退款當班現金。退款前需開啟當班、核對實際方式；不會自動向銀行發起退款。原收銀單不能從一般退貨／收款沖銷流程繞過。退貨後點數可為負，表示先前已使用的獲贈點數待後續扣回，不能繼續超額折抵。

結班填實際清點額；有差額必填原因，不會自動補一筆平衡收入／費用。收銀明細不是統一發票。

## 升級及還原

Node.js 維持 `.nvmrc` 的 24.22.0，沒有新增 npm 執行相依套件。Schema 由 3 透過版本 4–11 的加欄／加表遷移升級；既有交易列、帳款、總帳與流水不改寫。版本較新的資料庫會在寫入舊表前拒絕開啟。

先停止寫入業務，在資料庫的**副本**驗證，保留原程式版本與備份。可使用：

```sh
node scripts/pre-upgrade.mjs company
# 或指定目前環境的根資料庫，連同所有公司逐一備份／驗證
node scripts/pre-upgrade.mjs --db /path/to/root.sqlite --all-companies
```

腳本線上備份後，只對驗證副本套用遷移，逐表比較所有原有欄位與資料列雜湊，再跑一致性檢查；原庫不升級、不重寫。備份及 JSON 驗證報告在各庫旁的 `backups/`。缺少任何公司庫會拒絕繼續，不會建立空庫替代。

確認副本驗證與 `npm run verify` 通過後，再啟動相符的新程式。要回復，配對原程式與升級前根庫、公司庫、公司目錄關聯；不要以舊程式直接開新庫，也不要只還原根庫卻遺漏公司庫。單次 API 備份只包含目前選定公司，完整環境須逐公司備份。

## 已驗證及尚待驗證

自動測試涵蓋原流程、新交易、例外回滾、重送、權限、跨公司隔離與資料庫副本升級。瀏覽器亦實際操作作業分頁、表單、SKU／訂單匯入、批號、收銀、維修與公司切換，使用資料均為虛構。

正式公司資料移轉、20 人長時間負載、實體設備、發票／金流／物流服務與當期官方格式仍需各公司選定服務後驗證。本輪未使用正式公司庫、憑證、銀行帳號或實際扣退款。
