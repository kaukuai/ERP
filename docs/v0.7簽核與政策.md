# v0.7 簽核、補打單與逐人版型授權

左側新增「簽核與操作政策」。本版完成補充查核 M01、M04、V01 的下列軟體驗收範圍；補充 16 項現為 5 可操作、5 部分具備、6 待建置。原 115 項的狀態沒有因這次變更而調高，也不代表全部手冊功能均已對等。

## 報價單明細欄位重疊修正

已重現新增報價單中交易單位選單、稅率輸入框跨入相鄰儲存格的情況。原因是同格中多個寬度 100% 的控制項仍以行內方式排列。新版將控制項改為分行並限制在各自欄寬內，固定明細表欄寬；使用者調整欄位順序時，寬度設定隨對應欄位一起移動。小螢幕可在明細表內水平捲動，數量、單價與稅別不再互相覆蓋。

已在與回報接近的 1366 像素視窗及 150% 像素比例重現，再檢查報價／訂單／採購、6 種寬度、全部 6 種允許的輸入順序、空白／3 列長值／水平捲動狀態，共 326 個明細情境，逐一量測輸入框是否超出儲存格及彼此重疊；並實際選商品、計價及保存報價。既有 96 個視窗狀態也加上同樣的儲存格檢查。

GitHub 自動檢查新增瀏覽器工作，對實際打包的展示內容以 3 個輪替處理程序執行明細排版、既有視窗、簽核及自訂表單測試；全部通過後才建立 Windows 本機包。瀏覽器工具獨立安裝在測試機，不會成為本機 ERP 執行相依套件。可用 `node scripts/check-browser-demo.cjs tests/browser-document-layout.cjs` 在已安裝 Playwright 及完成展示建置的開發環境重跑。

## 條件式多階簽核

完整權限管理員到「規則」新增或修改規則，選擇報價、銷售訂單或採購，填含稅金額下限及上限（空白不限）。同類啟用規則的金額區間不可重疊；沒有符合規則的單據，沿用既有單階送審／核准。

每條規則可設 1–10 階，每階選指定人員或經辦人的上階，並選任一人核准或全部會簽。上階來自使用者的組織設定；這次不新增任意條件程式或流程圖。可禁止經辦人自行／代理核准，並禁止同一人或其代理跨階重複核准；同一實際簽核人也不能代替多人完成同一階的會簽。

送審時凍結規則修訂及當時具備來源核准權的簽核人。找不到可用人員、無法分配不同人完成各階時，不接受送審。已送審請求不因後續修改或停用規則而換成另一條規則。簽核人被停用或失去來源單據核准權後，不能繼續核准；由有權的簽核人退回，或依既有取消規則處理，再修改規則重新送審。

使用者從「簽核請求」開啟歷程，選核准或退回。來源單據的檢視、核准動作及資料範圍仍各自檢查。中間階段不預留庫存、不形成出入庫或帳款；最後一階才執行既有單據核准及庫存預留。最後核准遇到庫存不足，該次決定與單據異動整批回滾，補足庫存後才可重新處理。

退回原因必填。修改退回單據後重新送審，建立新一輪請求，保留舊輪決定。決定紀錄、規則歷史與請求中的規則快照不能覆寫。每次簽核須帶目前單據修訂，避免舊視窗核准到新階段。

目前引擎適用上述三類交易單據，不包含自由填寫表單、費用、盤點或其他模組的多階核准。會自動建立並核准訂單的直接交易、POS、排程等既有流程，也不能繞過符合的多階規則；設定之前須確認規則是否會涵蓋這些操作。規則預設為空，不改變既有未配置政策的流程。

## 限期代理

完整權限管理員到「代理」選原簽核人、代理人、開始／結束日期、適用單據及啟用狀態。日期依台北日曆，起迄日均包含。停用或到期即不能再代理；已完成的決定保留原簽核人與實際代理人。

代理不會授予來源資料或核准權，原簽核人及代理人都必須保有相應權限。代理不會繞過禁止自核、跨階同人及同階多人會簽限制，也不提供連鎖轉代理。

## 補打單期限

到「補打單期限」分別設定交易、庫存、帳務最多回溯天數。空白表示不另限制；0 表示只接受今天及未來，5 表示最早可處理五天前的日期，邊界日包含在內。

這個限制與既有總結帳日、模組結帳日同時生效，管理員的日常單據操作也受限制。政策修改有修訂衝突檢查與前後值稽核。修改既有舊日期單據、核准及過帳同樣檢查，不只限制新增畫面。這項設定不會改寫舊單據，也不是限制既有單據的重印或歷史查詢。

啟用政策前請確認月結、成本及其他以歷史日期過帳的操作；必要時由完整權限管理員核對並調整政策，保留稽核原因與操作記錄。新帳套預設不限。

## 逐人逐版型授權

到「版型授權」選表單或自訂報表，再選使用者。各動作可選沿用原授權、允許或拒絕。表單包含查看／修改版型、空白或交易列印、匯出版型、新增填寫，以及填寫紀錄的查看、修改、送出、取消、列印；報表包含查看、修改及列印。

版型設定與原功能動作、角色、資料範圍、成本及隱藏欄位限制取交集。單一版型的允許不會授予原本未開放的功能，也不會開放其他人的資料。拒絕查看版型會阻擋該版型的其他動作；填寫紀錄另外按紀錄動作設定，因此可保留舊填寫紀錄的查閱，同時停止開放原版型。完整權限管理員保留管理能力，可修正錯誤設定。

授權更新會撤銷目前所有登入連線並增加權限修訂，請重新登入。既有冪等請求也不能回傳撤權前的內容。權限變更有版本衝突與稽核，不能從直接 API、匯出、列印或舊網址繞過。這次不新增自訂表單每個欄位的個別遮蔽，M03 仍部分具備。

## 升級、驗證與剩餘工作

版本 0.7.0、schema 16；新增簽核規則／修訂、請求／決定、限期代理及版型授權表。原交易、總帳、庫存流水不改寫。先停止業務寫入並以 `node scripts/pre-upgrade.mjs --db 資料庫路徑 --all-companies` 在備份副本驗證，再啟動新版。

Windows 本機資料位置及升級前全帳套備份規則不變。從對應提交的 Actions 下載 `ERP-Windows`，完整解壓至新程式資料夾，關閉舊版後啟動 `start.cmd`。建置驗證不代表已安裝到使用者電腦；正式網站是否更新仍應核對部署分支。

驗證使用獨立資料庫與虛構展示資料，涵蓋循序／會簽、代理到期、跨階不同人、不可完成路徑、規則快照、退回重送、最後庫存不足回滾、撤銷權限、補打天數邊界、版型直接 API 限制及帳套隔離。瀏覽器實際新增兩階規則、切換兩位簽核人完成核准、檢查庫存只在最後一階預留、設定補打限制與撤銷版型授權，並檢查五個分頁在四種寬度的版面。本機 `npm run verify` 共 222 項通過；先前 v0.6 的三個虛構測試帳套副本升級至 16，原資料列完整保留且一致性檢查通過。最終跨平台、瀏覽器結果與 Windows 成品以本提交 PR／Actions 為準。
