## 本版模型

授權由公司帳套 → 基本角色／自訂角色繼承 → 個人覆寫 → 動作 → 資料範圍 → 欄位與交易狀態共同決定。人員範圍涵蓋本人、直屬／多層下階、同部門與指定使用者；動作與方向各自設定，不因上下階、同階或同帳套而互相開放。

個人規則取代相同功能、動作的角色規則；同層允許取聯集、拒絕取排除。部門範圍按使用者的組織部門，不等同交易上凍結的分析部門。共用主檔沒有擁有者時，應使用全部檢視搭配倉庫／分類，而非本人範圍。成本金額可見性是全域開關，配合交易本身的資料範圍使用。

完整權限管理員可管理授權；至少一位啟用管理員不能被移除。一般受限管理員不能藉使用者表單把自己升權。變更撤銷本帳套 Session、增加授權修訂並寫不可覆寫稽核；角色及主管關係拒絕循環。到期規則在新請求重新計算，寫入前再核對修訂與授權。

## 強制檢查與驗證

- GET 查詢在聚合之前限制來源列，子資料沿來源單據繼承可見性；不以回傳後裁剪代替報表限制。
- 寫入獨立檢查目標及批次來源；可讀同事單據不代表可出貨、沖帳或改資料。直接進銷貨與轉採購另核對必要動作。
- 庫存、授信及過帳內部計算仍使用完整帳套資料，避免資料範圍讓可用量或信用曝險被低估。
- 唯讀欄位省略時保留原值，改值會被拒絕。受限單價由伺服器核定，整單折扣也受折扣限制。
- 隱藏採保守跨資料集同名欄位遮蔽，相關衍生金額一併處理；含隱藏欄位的帳號目前不能使用原始欄位輸出。這是目前明確的能力邊界，不宣稱每一模組每一欄都支援獨立政策。
- 全庫備份、重建及跨帳套管理保留完整管理員權；各公司 SQLite、Cookie、CSRF 與授權保持獨立。
