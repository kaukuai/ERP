# v0.8 品檢放行與供應商請款三方核對

左側新增「品質與請款控管」，包含品檢待辦、檢驗規格、供應商請款與核對政策。本版完成補充清單 V02／V03 的下列軟體驗收範圍；補充 16 項現為 7 可操作、5 部分、4 待建。原 115 項仍是 95 可操作、6 部分、14 外部，不代表全部手冊或所有產業的 ERP 已完成。

新帳套沒有預設須檢驗規格，付款前強制三方核對也預設關閉。管理員應先設定公司實際使用的規則；開啟付款管制後，既有應付的後續付款也會檢查。政策、規格及單據均各帳套分開保存。

## 品檢規格與待驗隔離

完整權限管理員在「檢驗規格」新增商品及管制方向：採購入庫前或訂單出貨前。同商品、同方向只能有一個啟用規格。可設定抽樣比例、最低抽樣基本量及最多 30 個數值／文字參數。數值上下限包含邊界，最多四位小數；文字採去除前後空白後完全相符。參數是安全的固定規則，不執行公式或程式。

抽樣量採商品基本單位，與箱／包等交易單位分開；按比例計算後至少符合最低量，但不超過本批基本量，最小精度 0.001。每個參數填一組本批測量或綜合判定，沒有逐件樣本分布、統計 AQL、儀器校正或自動量測設備連線。

先建立並核准一般採購／銷售訂單，再從「品檢待辦」建立本批品檢，選來源與本次數量。可只處理部分未交量，系統凍結來源修訂、交易量、基本量及規格修訂。待驗或不合格的進貨不進入可用存貨，也不立應付；出貨尚未放行則保留原訂單預留量。

這是進出貨前的待驗流程，不是把已入庫商品自動搬入隔離儲位。既有庫存不會因新增規格而被追溯隔離；完整儲位台帳仍列 V04 待建。

## 登錄、判定、放行與進出貨

檢驗人員填實際抽樣量與各參數讀值，可先保存不完整草稿。送出判定時檢查全部必填參數與最低抽樣量，伺服器判斷合格／不合格，不能由用戶端直接宣告合格。送出後鎖定讀值；不合格可另建新單重新檢驗，原單、結果與事件保留。

規格可要求建單人及登錄過讀值的人不得自行放行。核准者還需具備該品檢的核准權及來源檢視權；檢驗、放行、取消與實際過帳可分開授權。已放行單按「使用此放行單進出貨」會帶入原本批量，也可從原單的進出貨視窗選擇放行單。

放行綁定來源修訂及完整本批數量，不能拿來處理別張單或不同數量。若本批已有較新的草稿、不合格或取消紀錄，不得退回較舊放行單；取消新單也不會復活舊放行。來源先有其他部分進出貨，原放行需重新核對。本批完成一次進出貨後即用訖，不得重複使用。

放行單使用紀錄與庫存／帳務在同一交易內，庫存、批號或後續過帳失敗會整批回滾。合併進出貨 API 可逐來源提供 `quality_inspection_id`，其中一張未放行會回滾全部來源。待驗規格尚有未結單時不能直接停用或改商品／方向，須先完成或記錄原因取消；修改規格內容只影響後續建單，舊快照保持原值。

管制範圍為一般訂單出貨與採購入庫，含部分、合併、直接呼叫 API 及舊計價來源。非交易調整、調撥、借還貨、退貨、組拆裝尚未具相同的通用品檢管線。會自動建單、核准、過帳的 POS 或直接交易若遇到須品檢商品，也不能繞過管制；請採一般訂單流程，或先核對商品規格設定，不將這視為已完成實體設備整合。

## 獨立供應商請款憑證

從「供應商請款」選供應商，勾選實際進貨來源，輸入供應商憑證號、日期、數量、未稅、稅額及憑證總額。總額須等於所選明細合計；同供應商的有效憑證號不分英文字母大小寫，不可重複。取消後可另建更正版並保留舊單。

來源可搜尋最近 500 筆，輸入完整採購或進貨單號可查更舊資料。查詢時保留已勾選的明細與尚未保存的憑證欄位。每張請款最多 200 列，可涵蓋多張進貨。

本版按每張進貨單的全部未退明細核對，不支援同一張進貨拆成多張部分請款；分批請款須先分批進貨。舊計價未保存逐列稅額，或含無明細分配的舊整筆折讓時，不會推估數字，須先保留強制管制關閉，用原流程由財務核對處理。尚有這類未結應付時，系統會拒絕直接開啟強制管制；啟用後也不接受新的舊計價採購入庫，須先結束舊單未交量，改以新版採購處理。

系統使用採購的原商品／交易單位及進貨快照，扣除實際退貨與逐列折讓，核對數量、單價、未稅金額及稅額。已由其他有效請款核准的進貨，不能再重複核准。核對發現差異時保留草稿及原因，不能直接付款。

## 容忍、核准及付款管制

完整權限管理員可開啟付款前必須核對，分別設定數量與單價／未稅金額的容忍基點（最多 10%）及每列稅額容忍（最多 100 元）。單價與未稅金額會同時檢查，不能用數量差異掩蓋不符單價；預設容忍皆為零。

核准前須重新取得目前來源及政策的核對結果。請款內容、來源或政策有異動時，舊預覽不能核准。可禁止建單或修改請款的人自行核准；容忍內仍有差額時，需明確確認並填原因。

核准只保存核對授權及不可覆寫的來源／政策快照，不重複立應付、不調整存貨成本，也不自行開立或驗證正式發票。付款仍依 ERP 帳款餘額；如憑證差額確實要改帳，應先使用適當的原交易更正、退貨、折讓或費用流程，再重新核對。

強制管制啟用時，單筆／批次／月結付款、預付款沖抵、票據及背書等增加應付已沖金額的操作，都由同一資料庫限制檢查。未核准或來源已異動，整筆操作失敗；月結多來源中後一張未核對，前面已處理的付款也會回滾。

退貨、折讓或帳款金額變動會使先前核對失效，後續付款須先取消舊核對，依目前來源餘額另建並核准。取消請款不沖銷已存在的付款或實際轉帳；需要沖銷時仍用原收付流程。本版沒有自動寄送憑證或向銀行發起付款。

管制適用有進貨來源的應付帳款；期初應付及未綁定進貨的預付款是不同流程，不會假造三方來源。預付款日後沖抵應付時，仍須通過核對。

## 權限、升級及驗證

新增「品質檢驗規格」「品質檢驗與放行」「供應商請款與三方核對」權限項目，可設定動作及本人／下階／指定人員／倉庫等範圍；請款的倉庫／分類限制會檢查全部來源，不能改來源後逃出授權範圍。

未自訂細部授權時，一般帳號可依原來源權限唯讀查品檢；倉管／主管可填寫，主管或管理員可放行。財務／主管／管理員可登錄請款，主管／管理員核准；請款檢視另要求成本可見，來源有隱藏欄位時採保守限制。獨立品檢讀值按整筆品檢及來源範圍授權，不會因參數名稱恰與成本相同而漏掉測量值。

版本 0.8.0、schema 17，加表／索引／觸發器，不改寫原交易及流水。先停止業務寫入，執行 `node scripts/pre-upgrade.mjs --db 資料庫路徑 --all-companies` 在備份副本驗證，再啟動新版。Windows 資料仍保存在原本使用者資料夾，升級前完整備份與副本驗證規則不變。
