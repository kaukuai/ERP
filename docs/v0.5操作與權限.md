# v0.5 操作、權限與升級

本版補齊 24 項原「部分具備」的軟體驗收範圍。115 項目前為 95 可操作、6 部分具備、0 待建置、14 需外部整合。狀態只涵蓋各列驗收條件，不代表全部 ERP 已完成或可直接切換正式帳務。

## 管理員設定

登入後開啟「系統與資料管理 → 使用者權限 → 組織與細部權限設定」。先建立一般帳號，再設定直屬上階、部門、自訂角色與個人規則。各公司帳套分別設定，不會跨公司繼承。

- **基本角色**：可保留原六角色授權，或改成僅依自訂角色及個人規則。選擇後者時，未明確授權的功能不開放。
- **上下階**：只記錄組織關係，不自動授權。可針對檢視、修改、核准等動作，分別設定本人、本人與直屬下階、指定深度下階、同部門或指定使用者。
- **彼此存取**：A 要看 B 的訂單，在 A 的訂單檢視規則選指定使用者 B；B 要看 A，另設反方向規則。修改、過帳、退貨與核准都要各自授權。
- **角色與個人覆寫**：角色可多重繼承；同功能同動作有個人規則時，以個人規則取代角色／基本授權。同層允許取聯集、拒絕優先。只有拒絕規則而沒有允許時，該動作不開放。
- **倉庫、分類與期限**：可限制資料所屬倉庫及商品分類，或指定到期時間。成本金額可見性是全域開關；人員與倉庫範圍另設在各交易功能。
- **欄位**：商品、往來、報價、訂單及採購的常用聯絡、信用、價格、成本、折扣及備註欄位，可設可修改、可見唯讀、隱藏。可修改欄位仍需要該功能的修改權。

例如：主管可檢視兩層下階的訂單，但只改自己的草稿，可設定訂單「檢視 → 下階、深度 2」及「修改 → 本人」。若不得核准自己的單據，再加「核准 → 允許下階」及「核准 → 拒絕本人」。相關客戶、商品、倉庫也須有檢視權，才能顯示完整單據。

可用「有效權限試算」核對規則。修改權限會撤銷本帳套所有登入，請重新登入。至少保留一位啟用的完整權限管理員；完整管理員不受細部規則限制。安全授權、完整資料庫備份、帳套建立、成本政策及重建等入口仍由完整管理員操作。

伺服器會檢查單筆 ID、批次來源、合計及冪等重試，檢視他人資料不代表能操作。隱藏欄位採保守遮蔽，相關同名欄位及衍生金額可能一起隱藏；目前含隱藏欄位的受限帳號不能使用原始欄位列印、匯出或分析。需要輸出時，可改用「可見唯讀」並另授予輸出權。詳細研究與技術邊界見 [權限設計與參考資料](權限設計與參考資料.md)。

## 完整營運作業

左側新增「完整營運作業」，依權限提供下列入口。

| 分區 | 操作 |
| --- | --- |
| 進出庫與組拆裝 | 非交易進出庫草稿 → 核准 → 過帳；調撥發出 → 在途保管 → 分次驗收；成品拆解、展開材料的組合銷售、缺貨訂單部分配置。 |
| 分類與補貨 | 多層分類、型別自訂欄位、商品屬性；目標量／最低量／倍量補貨，按供應商建立多品採購草稿；批次參考成本或分倉庫存價值匯入。 |
| 盤點控制 | 純值 XLSX／CSV 欄名映射、區域標記、分批儲存、差異預覽與異動重基。區域標記不等於完整儲位庫存。 |
| 收付與結帳 | 期初預收付、混合收付款、核對退款後沖銷、本地憑證來源關聯、負責人指派、成本政策及模組試算／結帳／重開。 |
| 歷史與矩陣 | 往來關聯、歷史庫存與庫齡、歷史帳齡與可列印對帳單、多維交叉矩陣及 CSV。單據明細也可直接開「交易關聯」。 |
| 個人設定 | 每人數量／金額顯示位數與數量、單價、折扣欄的輸入順序，底層精度不變。 |

混合收付需選同一往來與方向，輸入本次沖抵金額，再分配實際銀行、現金、票據及既有預收付。內扣手續費計入應收沖抵；額外銀行費用另記費用及銀行支出，不抵減供應商應付。超額須明確確認，且只允許現金／銀行超額轉預收付，不虛構票據或金流成功。

期初預收付對應期初權益，不假造銀行款。折讓保存當時逐列金額，後續實物退貨扣除已折讓部分，避免重複退款。採購折讓可列損益或減存貨價值，庫存價值不足時阻擋。舊計算版本或沒有逐列分配的歷史折讓，仍須財務核對。

收付款已有後續退款時，沖銷會先要求核對；確認後抵減本次實際沖銷現金，保留原退款與收款紀錄。待退款若已沖抵其他帳款，先阻擋，不能靜默撤銷其他帳款。

標準成本啟用前須設定所有庫存商品的標準成本。入出庫保留原交易與差異分錄，不能另用一般成本重估繞過政策。月加權採月內暫時計價、月末結算並關閉庫存期間；若含組拆裝、借用等複合來源，會阻擋自動結算，這部分仍列 I10 差距。庫齡按本倉入庫與先進先出數量估計，不是原製造日期。貢獻利益含已分攤銷售費用，仍不是公司淨利。

## Windows 備份與升級

本機資料仍位於 `%LOCALAPPDATA%\ERP-Local` 或原先記錄的位置，不放進程式包。新版完整解壓至另一資料夾，關閉舊版後啟動 `start.cmd`；啟動器先備份全部帳套並驗證副本，找不到已知資料庫時拒絕建立空庫替代。

新增 `schedule-backup.cmd` 可登錄每日備份工作，預設保留 30 組驗證成功的完整帳套備份，可選第二磁碟或網路資料夾複製。電腦須開機且使用者已登入；ERP 視窗開啟或關閉皆可備份。變更程式資料夾後請重跑排程設定，避免工作仍指向舊程式。手動 `backup.cmd` 與升級備份不受排程輪替刪除。

每組排程備份含 `manifest.json`、根帳套及公司目錄。可用隨包 Node 執行 `app/scripts/backup-service.mjs --verify 完整清單路徑`，在暫存副本檢查雜湊、升級、庫存、帳款與總帳。請保存整組，不能只拿單一 SQLite。第二位置複製與自動驗證，仍不能取代實際異機災難復原演練。

Schema 升級至 14，以加表、加欄保留既有資料；先執行全帳套備份及副本驗證。自動測試只用虛構、獨立資料庫，不在正式帳套測試交易。既有部署與互動展示方式保留，展示不是正式持久儲存。
