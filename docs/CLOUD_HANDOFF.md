# ERP 雲端工作交接 · v0.4.3

後續開發使用 Codex Cloud 的 `kaukuai/ERP` checkout；不依賴原 Windows 電腦、正式公司資料庫或憑證。

## 使用者本輪確認

- 範圍為原清單全部 20 項待建置，逐項實作與驗證。
- 產品供各家公司使用，不限原單一公司情境。
- 多公司採各自獨立登入，另行授權管理彙總。
- 維修、寄售、租賃依已有手冊對標需求制定流程。
- POS 門市、收銀人員、設備與收款方式由使用者在系統設定；設定不代表外部設備或金流已驗證連線。

## 最新使用者要求

使用者要求之後 GitHub 更新之外，也同步提供在其 Windows 電腦執行、關閉後仍保留資料的本機版本。此處的電腦是使用者自己的 Windows PC，不是雲端工作區；目前沒有遠端安裝權限或桌面存取。已建立 Windows 本機包與自動建置／驗證／成品上傳流程，資料存放於 %LOCALAPPDATA%\ERP-Local（既有資料會沿用原位置），升級前完整備份與副本驗證，遺失已知資料庫時拒絕建立空庫。

開發仍在雲端，以 GitHub 程式碼與可下載本機包交付；不宣稱已安裝至使用者 PC，不將正式資料上傳。主分支更新先前遭自動審查拒絕，PR #1 已建立，使用者尚未明確批准合併；本輪僅更新功能分支及本機包。


使用者明確要求部署可操作的網頁展示，明確接受沒有獨立後端及資料不永久保存；另外詢問單機使用。v0.4.2 已加入預設互動展示、分頁隔離、加密狀態、跨函式延續、列印／匯出及重置。正式模式 ERP_MODE=production 仍要求持久化後端，不能以展示當作正式儲存。單機網頁服務與 SQLite 同機，不需另租主機。見 [展示與單機操作](v0.4.2展示與單機操作.md)。

## 目前版本與驗收

Node.js 24.22.0、ES modules、內建 node:sqlite，沒有新增 npm 執行相依套件。Schema 版本 12，透過加表／加欄從 v0.3 升級，保留既有欄位及資料列。

```sh
node --version
npm run verify
npm run dev
```

新增操作集中於「交易作業中心」。完整入口、20 項範圍、備份升級與限制見 [v0.4 操作與升級](v0.4操作與升級.md)。功能狀態以 `src/capabilities.mjs` 為來源，執行 `npm run capabilities` 產生 Markdown 與 JSON。

115 項需求目前為 71 可操作、30 部分具備、0 待建置、14 需外部整合。原 20 項中 18 項依所列範圍可操作，E08 與 X10 仍部分具備；另完成 B10 月結政策。**待建置數為 0 不表示整個 ERP 完成或已可正式切換。**

## v0.4.1 部署修正與匯入（歷史）

使用者回報舊版 main 在函式平台建置成功、執行時 FUNCTION_INVOCATION_FAILED。新增網站代理入口與容器後端，SQLite 保存在持久磁碟；不得將暫存目錄當成正式持久儲存。見 [雲端部署](雲端部署.md)。實際平台部署仍需後端 HTTPS 網址及環境變數，使用者回覆尚未準備持久化後端；目前沒有取得正式部署存取權或 Runtime Logs。已提供 render.yaml 的單一後端／持久磁碟模板，建立服務前需由使用者於平台確認費用。

B13 已新增純值 XLSX／CSV 商品、往來及期初庫存匯入，保存映射與固定值、來源雜湊、範本修訂檢查、整批交易；入口為系統與資料管理 → 舊資料匯入。README 與更新說明使用中性名稱，不含客戶、示範或參考廠商的公司名稱。

## v0.4 實作

- B02：獨立公司 SQLite、管理員、倉庫、Session Cookie、CSRF 與逐公司授權／撤銷的彙總；主要帳套代碼 default。
- B28：欄位、版型、紙型及分開的檢視／列印角色，保留資料範圍與成本限制。
- P05／S07：有獨立合併單號的合併進出貨、逐列部分量、原來源／退貨與列印，任何來源失敗整批回滾。
- S02：明細分期日期、調整、跳期、暫停／恢復、到期出貨與不可覆寫事件。
- S03／S04／C02：外部與發票欄位、來源單號去重、精確一對一 SKU／單位映射、CSV 範本、預覽／例外與原子匯入。
- E02／E03：雙月字軌、重疊／空白／使用狀態、空白作廢、設備／紙型／捐贈碼／抬頭圖與非正式校樣。
- F02／B10：逐次或批次政策，待立帳科目、截止後合成應收／應付帳單、部分收付、退貨、列印及防重複。
- F03／F09／F11：呆帳提出／核准／駁回／收回／沖回，XLSX／CSV 銀行精確與人工對帳，費用按金額／數量與核對去向分攤。
- T06／T07：記名／劃線／轉讓限制、背書與退回／退票／受讓人兌現、員工及其他對象票據與費用連動撤銷。
- X08：批號、唯一序號、效期分配、跨倉調撥、原來源退貨及不可覆寫批號流水。
- X09：維修／保固／領料／收費，寄售保管與售出立帳，租賃資產、逐期租金與獨立押金。
- E08／X10：已建立本地發票交換及 POS 軟體流程，保留以下未完成驗證。

## 尚未完成的外部範圍

E08：當期官方／加值中心 TXT／CSV 格式、正式漏號回報及真實回執仍未驗證。現有自訂欄位交換、筆數金額校驗及來源雜湊不能取代此驗證。

X10：實體掃碼器、印表機、正式發票及金流 API 整合仍待選定服務商／設備後實機驗證。目前外部終端模式只登錄使用者已核對的實收成功參考號，不會自動扣款或退款。收據不是統一發票。

原有其他 28 項部分具備及 14 項外部整合仍須逐列驗收，包括正式資料移轉、負載／維運、發票開立、平台及物流，不能自動標成完成。未標示的製造功能不在本輪範圍。

## 後續工作規則

開始先讀 AGENTS.md、v0.4 操作與升級、最新驗收清單，核對實際執行位置與提交、保留使用者修改，再執行完整驗證。只有確定環境已發布並在新任務還原後，才回報完成發布／還原驗證。

不要從歷史交接文字推定使用者授權無限擴充功能；依新任務範圍處理。涉及 E08／X10 時先核對公司選定服務、官方格式與實機／回執，不能以設定值或模擬成功作完成證據。

每次公司庫升級先備份並驗證副本；多公司須連同根庫、公司庫與目錄關聯保留。可用 `node scripts/pre-upgrade.mjs --db /path/to/root.sqlite --all-companies`。完整原始資料不加入 Git。

使用功能分支與可審查提交／PR 交付；保留整數金額／數量、原子交易、不可覆寫庫存／總帳／稽核、修訂衝突、CSRF、權限、冪等及公司隔離。正式服務部署與環境發布屬另行確認的行為。
