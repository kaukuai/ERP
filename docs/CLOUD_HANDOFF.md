# 成祥 ERP 雲端工作交接

使用者要求：後續開發工作改在雲端進行，不再依賴原 Windows 電腦。

## 專案與已確認需求

- 原始碼：https://github.com/kaukuai/ERP ，預設分支 main。開始工作時先確認最新提交，不覆蓋之後的使用者修改。
- 系統為繁體中文買賣業 ERP，完整取代原進銷存；約 20 人，不需要自製生產。
- 倉庫、客戶、廠商、商品及其他主檔要能自行擴充。
- 業務能查資料、修改報價／訂單、產生可列印的黃單；黃單即報價／訂單。
- 依凌越、數碼一號原廠手冊、國內外及開源 ERP 研究補齊功能。需求與來源已存在 repo 文件中。
- 採用公司授權流程、成本遮蔽、資料範圍與可追溯庫存／會計設計。

## 可重建的環境

Node.js 24（.nvmrc 記錄 24.22.0），ES modules，內建 node:sqlite。沒有 npm runtime 依賴；條碼元件已包含在 vendor 並保留授權。

```sh
node --version
npm run verify
npm run dev
```

- npm run verify：完整語法與測試。交接時基準為 101 passed、0 failed；Windows／macOS／Linux 的 GitHub Actions 均曾通過。
- npm run dev：啟動虛構示範工作空間，本機埠 4321。
- npm run dev:company：啟動這個開發環境的獨立空白公司庫，本機埠 4320；不要放入正式公司資料。
- Codespaces 與 Dev Containers 設定已存在，但不等於 Codex Cloud 已完成環境發布。
- 雲端預覽若提供外部主機，僅加入該環境實際分配的精確主機白名單；保留 Host／Origin／CSRF、Session、權限與示範 loopback 限制。

## 目前實作狀態

版本 v0.3 核心試行版，尚未達到全部功能對等。現有 115 項驗收需求：51 可操作、30 部分具備、20 待建置、14 需外部整合。以 src/capabilities.mjs 與 docs/數碼一號功能對標與驗收.md 各列驗收範圍為準，不把項目數當工程完成百分比。

已可實際操作的範圍包含：報價／訂單黃單、審核預留、分批進出貨、退貨折讓、預收付沖抵退款、應收付與票據、庫存調撥盤點、借貨、主檔聯絡組織、匯入預覽、單位快照、逐列稅別、整單折扣尾差、直接進銷貨、剩餘結案、掃碼批次揀貨、圖片及條碼標籤、成本重估、單號規則、交易分析及受控庫存／帳款重建。

## 接續工作的第一步

1. 確認正在已發布的 Codex Cloud 環境中，checkout 為 kaukuai/ERP 的最新狀態；明確回報執行位置與 commit。
2. 讀 AGENTS.md、README、docs/v0.3操作與升級.md、docs/架構與API.md、docs/上線缺口與開發順序.md 及最新功能清單，執行 npm run verify。
3. 接續使用者已授權的「把待建置部分建置完成」。優先處理可獨立驗收的核心買賣流程，例如 P05 多採購單合併進貨、S07 多訂單合併出貨，再處理 F02 批次月結立帳；避免只補選單、靜態頁或文件。
4. 每一項都包含儲存層、交易一致性、角色權限、可操作介面、列印／來源追溯及重要例外測試；依結果更新清單，執行 npm run capabilities 重新產生文件。
5. 使用功能分支與可審查的提交／PR 交付，說明實際完成、測試與剩餘差距。保留既有總帳、庫存流水及稽核不可覆寫，錯誤必須整筆回滾。

## 資料與安全邊界

公司正式 SQLite、帳密、備份及完整廠商 PDF 未上傳 GitHub。正式資料仍在原公司環境，雲端開發使用記憶體／暫存資料庫或虛構示範資料，不需要讀取原裝置。不將資料庫、環境秘密或憑證 commit；不建立正式電子發票、不代替使用者執行銀行交易。此交接沒有部署公司的正式共用 ERP 服務。

## 雲端任務可直接使用的接續指令

> 從雲端接續 https://github.com/kaukuai/ERP 的 ERP 開發。先讀 AGENTS.md 與 docs/CLOUD_HANDOFF.md，核對最新 commit 及 npm run verify。保留既有公司需求、財務／庫存一致性及權限。接續待建置功能，先實作 P05 多採購單合併進貨及 S07 多訂單合併出貨，完成介面、來源追溯、權限與交易例外測試，再更新功能驗收清單並提出可審查提交／PR。所有修改、執行與驗證在雲端 checkout 進行，不依賴原 Windows 電腦或正式公司資料，不把未完成或外部介接標為完成。
