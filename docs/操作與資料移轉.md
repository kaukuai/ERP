# 操作與資料移轉

## 啟動與初始化

1. 在專案目錄雙擊 `demo.cmd`，或執行 `node src/server.mjs --demo`。
2. 打開 `http://127.0.0.1:4321`，按「進入示範工作空間」。資料完全虛構。
3. 公司工作空間使用 `start.cmd` 與 `http://127.0.0.1:4320`，由使用者建立管理員及密碼。
4. 到「系統與資料管理 → 公司設定」填表頭資料，並建立各部門帳號。
5. 到「庫存與倉儲 → 倉庫資料 → 新增倉庫」自行擴充倉庫，不需改程式碼。

這兩個網址只開放目前這台電腦。20 人或手機在外使用，需要公司管理主機與 HTTPS 部署；不要把 `127.0.0.1` 傳給其他同事當作公司伺服器網址。

## 基本資料

先建立倉庫、廠商、商品，再建立客戶與客戶專屬價格。商品類別、單位與規格可自行填寫；一個品號目前只有一個基本單位、一個條碼與一個主要供應商。

商品「參考成本」只供預填、零庫存盤盈及借入估值，不會改寫現有庫存帳面金額。原有庫存必須從期初匯入、進貨或經核准的調整取得。

客戶信用額度 0 代表不設上限。主管應確認新客戶條件；業務可新增客戶，但不能自行指定信用額度、付款天數或其他負責人。

付款天數以實際出貨／進貨日期加天數計到期日，**尚不是月底結帳後再加天數的月結模式**。若公司採月結，必須在正式切換前調整規則。

## 報價、訂單與黃單

1. 業務進入報價或訂單頁建立草稿。
2. 選客戶與倉庫，再選商品。客戶專屬價格優先，沒有才帶商品標準售價。
3. 畫面顯示所選倉庫的可用量，已扣除所有訂單預留量。
4. 輸入數量、單價、逐列折數、稅別、日期、送貨地址與備註。
5. 儲存草稿後仍可重新編輯。別人已更新的舊版本會被阻擋，請重新載入。
6. 按「黃單／PDF」預覽。可切換 A4 或 A5 橫式；按「列印／另存 PDF」使用瀏覽器功能。尚無伺服器直接下載 PDF 端點。
7. 用黃色紙列印可關閉背景；若要印出黃色底，請開啟背景圖形。紙張、縮放、邊界與印表機驅動需實機確認。
8. 草稿、待審、退回與取消狀態會顯示提醒。黃單是報價或訂購文件，不是統一發票。

報價送審、核准後可轉為訂單草稿。轉單保留原資料，請再次確認訂單交期與收貨地址；報價只可轉一次。

## 核准、出貨與收款

送審後由管理員或主管核准。核准會檢查客戶信用暴險：未結應收＋已核准未交訂單＋本次訂單；也會檢查指定倉庫的可用庫存。

核准訂單才預留庫存，尚未扣實體量。倉管選「執行出貨」，填本次各列數量，允許分批、各列不同進度；全部為 0 或超出未交量會被擋下。

出貨會同時扣庫存、減少本單預留、增加已交量、建立應收及會計分錄。狀態轉為部分交貨或完成。財務在應收頁點「收款」，可部分沖帳；不能超過未結餘額。這只登錄帳務，不會連線銀行實際收款或匯款。

尚無交貨的核准單可由主管填原因取消，並釋放預留。已有交貨的原單不能直接取消；剩餘量終止尚未提供。

## 訂單轉採購與收貨

缺貨的訂單可先保持待審，主管在單據內按「轉採購草稿」：

1. 選供應商、預定到貨日。
2. 逐列填採購數量，沒有要買的列填 0。
3. 畫面列原訂單未交量、已連動採購量及本次數量。伺服器再次檢查累計量。
4. 存為採購草稿後，確認價格與條件，再送審核准。
5. 倉管按實際數量分批入庫，增加庫存並建立應付及總帳。
6. 商品到齊後重新核准原銷售訂單，再執行出貨。

不同供應商可分次建立採購草稿。來源訂單已有有效採購時會限制修改；取消未完成採購後才可重新規劃。已收貨的採購不能直接取消，應按進退流程處理。

「補貨建議」用全倉安全量、全倉可用量、已核准採購未交量估算。點按只會預填新的採購草稿，仍須人員檢查；草稿與待審採購不列入在途量。

## 庫存調撥、調整與盤點

調撥指定來源倉、目的倉、商品與數量，一次完成一出一入。不能取用被其他訂單預留的量；不改變全公司存貨總額。

調整由主管操作。正數增加、負數減少，必須填原因；增加時填單位成本。每筆留下庫存流水及帳務效果。

正式盤點流程：

1. 暫停該倉庫出入庫，建立盤點單取得帳面快照。
2. 實盤欄位**預填帳面量**，必須逐項核實與修改，不是已完成現場盤點的證據。
3. 「儲存實盤」只保存盤點單，不修改庫存。
4. 主管確認後選「儲存並過帳差異」。
5. 如果快照後有庫存流水，會要求取消並重建盤點；如果盤虧侵用預留量，也會阻擋。
6. 差異過帳留下盤點單、庫存流水與會計分錄。無差異時保留完成紀錄。

安全存量是全倉合計標準，不是每一倉各有同樣安全量。本版尚無儲位、批號效期、序號、待驗倉與轉倉在途狀態。

## 退貨、借還與帳齡

「庫存與倉儲 → 出入庫與退貨」由原單選退貨，填可退範圍內的數量及原因。銷退回原出貨倉；進退由原收貨倉退出。原訂單的已交紀錄保留，不會自動重新欠交。

v0.2 退貨如超過尚未沖帳金額，會將已收付部分建立待退款，後續到「資金與票據」選帳戶、金額、日期記錄實際退款。原始 API 若未帶 allow_credit:true 仍會阻擋，避免舊客戶端無意建立退款義務。有未兌現票據或先前金額折讓時，需先完成核對，本版會阻擋直接退貨。詳細規則見 [v0.2 操作與升級](v0.2操作與升級.md)。

「借貨與歸還」可登錄樣品借出或外部借入，再依實際數量分次歸還；借出與銷售不同，借出成本保留為借出資產。應還日過期且未還的資料會提醒。

帳齡分析按目前未結餘額及到期日分成未到期／今日到期、1–30、31–60、61–90、90 天以上。不是任意歷史基準日的帳齡重建。

## CSV 匯入與轉換

系統管理員先下載備份，再到「舊資料匯入」下載模板、選檔、預覽、確認提交。單次最多 2,000 列及 2MB；UTF-8，支援雙引號、逗號與欄內換行。

| 類型 | 欄位 |
| --- | --- |
| 商品 | sku,name,spec,category,unit,barcode,price,cost,safety_qty |
| 往來 | code,name,kind,contact,phone,email,tax_id,address,payment_days,credit_limit,notes |
| 期初庫存 | sku,warehouse_code,qty,unit_cost |

kind 為 customer、supplier 或 both。金額與數量使用一般十進位數字，例如 120.50、12.500；不要先乘 100／1,000。付款天數與信用額度應明確填寫。

商品品號、往來代號與條碼重複會被擋下。期初庫存要求已建立商品與倉庫，且該品／倉沒有任何庫存流水。整批匯入在同一交易寫入，任何錯誤都回復；提交後不能再次提交同一批次。

目前只提供新增式匯入，不會用相同代號更新既有資料。預覽通過到提交之間若他人先建立重複資料，也會回復整批並報錯。

匯出 CSV 會為容易被試算表當成公式的文字加防護字首；需要回匯時要檢查代號文字，不能把所有營運匯出檔直接當作原樣移轉模板。

**尚未提供的匯入**：歷史單據、期初應收應付、期初銀行現金、完整總帳、歷史已收付款。這些需要公司匯出樣本及欄位映射，不能靠截圖推算。

## 備份與還原

管理員在系統頁下載資料庫備份。使用 SQLite 線上備份機制，保留當時完整資料，不依賴直接複製正在寫入的主檔。下載後應存到公司受控位置，與原主機分開保存。

還原演練：

1. 在獨立目錄準備專案副本與備份檔，**保留原公司資料檔**。
2. 確認原服務已停止，或以另一個連接埠測試，避免覆蓋正在使用的資料庫。
3. 將 `ERP_DB` 指向備份副本，以 `PORT` 指定測試連接埠，再啟動服務。
4. 登入、比對單據筆數、期初與未結餘額，執行一致性檢查。
5. 驗收後再安排正式切換；切換前先備份當下公司資料。

不要只在運行時複製 `company.sqlite` 而忽略 WAL 狀態，也不要把備份直接覆蓋到仍在使用的檔案。備份含公司與登入資料，需作權限與加密保存。現版不含自動排程或異地留存功能。

## 正式替換的切換順序

盤點公司規則 → 舊系統完整備份 → 取得各類匯出 → 建欄位映射與代號對照 → 在測試環境轉換 → 對庫存數量及金額 → 對應收應付 → 對總帳 → 各角色實際試單 → 測試列印及備份還原 → 負載與權限驗收 → 選定切換日 → 凍結舊系統寫入 → 最後增量轉換與簽核 → 新系統啟用、舊系統保留唯讀。

先取得真實匯出與對帳結果，才能判斷全面替換日期。測試通過或畫面完成不能代替公司的資料與會計驗收。
