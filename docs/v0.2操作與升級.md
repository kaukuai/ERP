# v0.2 操作與升級

更新：2026-11-02。配合參考系統操作手冊比對的首輪實作。完整差距見 [功能對標與驗收](功能對標與驗收.md)，不能以這次補強作為全面取代舊 ERP 的宣告。

## 新增入口

| 入口 | 用途 |
| --- | --- |
| 功能對標與驗收 | 查來源頁次、現況、驗收條件；可搜尋、篩選與下載 CSV |
| 聯絡與組織 | 新增／修改多位聯絡人與地址、主要資料；主管新增部門與員工 |
| 資金與票據 | 預收付、待退款、銀行現金、票據、費用、期初帳款及資金履歷 |
| 客戶／廠商編輯 | 月底／指定截止日、付款天數及售價政策 |
| 商品編輯 | 標準、零售、批發與網路價 |
| 帳款與會計 | 應收付含期初餘額，新增金額折讓；期初帳款走獨立沖帳入口 |

業務只能維護有權存取的往來資料，不能替客戶提高信用或修改付款條件。財務與主管可執行資金功能，倉管與唯讀帳號不會收到資金餘額及帳號。員工主檔與系統登入帳號分開管理。

## 帶價、送貨地址及月結條件

選客戶後，商品依「客戶專屬價 → 該客戶價格政策 → 標準價」帶入。最近價格取最近核准、部分完成或已完成的訂單，不取未核准草稿。業務仍能修改草稿價格。多個地址在建單時以按鈕選用，儲存後保留送貨地址文字。

交易日起算：交易日加付款天數。月底：當月月底加付款天數。指定截止日：交易日未超過截止日歸本期，超過則歸下一期，再加付款天數；短月取該月最後一天。例如 12 月 26 日、截止日 25、付款 10 天，到期日為次年 2 月 4 日。

本版仍於每次出入庫立一筆帳。設定月結條件不會變成「延後到月底合併立帳」。已存在帳款的到期日不因修改客戶條件而追溯更改。

## 預收付款與退款

1. 到「銀行與現金」新增公司自己定義的銀行／現金帳戶及核准期初餘額。這只建立 ERP 記帳帳戶，不會開立真實銀行帳戶。
2. 「新增預收／預付」選對象、帳戶、金額，可指定訂單；指定後只能沖抵該訂單產生的帳款。
3. 「沖抵」選同對象及同方向的未結帳款；可分次進行，不再動銀行。
4. 「退款」從未用餘額分次退回，記錄實際帳戶、日期與說明。客戶退款扣銀行，廠商退款入銀行。
5. 已收付的實物退貨會先減未結部分，超過未結金額則建立待退款；後續到本頁完成退款收付紀錄。

餘額 = 原額 − 已沖抵 − 已退款，必須大於或等於零。跨客戶、跨方向、超額、指定訂單不符會整筆阻擋。現金帳戶不允許負餘額；銀行可為負值以表達透支，但本版沒有授信額度管理。所有動作僅記帳，不會連線銀行或執行實際匯款。

## 批次沖帳與金額折讓

「批次收付款」先選應收／付與往來對象，再逐筆填本次沖帳金額。上方收付款總額必須等於明細合計；任一筆失敗會整批回滾。目前一批使用一個帳戶，尚不支援一張收款單混合票據、現金、手續費及溢收自動轉預收。

「金額折讓」不動庫存。已收款部分會建立待退款；原單的累計折讓加退貨不得超過原金額。此版本做過金額折讓後，會阻擋同來源再次實物退貨，直到逐列折讓分攤規則完成。未兌現票據關聯的帳款先處理票據再折退。採購金額折讓的未稅部分目前記存貨調整損益，尚未做庫存／已售成本分攤。

收付款輸入錯誤時，可到「收付款更正」作反向沖銷；保留原紀錄與沖銷紀錄。來源已有退貨／折讓時會阻擋，不能以刪除原收付款繞過。

## 票據

登錄票號、應收或應付、對象、指定銀行、票面金額、到期日與沖帳來源。票面金額必須等於分配帳款合計。

- 應收：已收票 → 託收 → 到期兌現。
- 應付：已開票 → 交付 → 到期兌現。
- 未兌現可退票或作廢，恢復原應收付；已兌現不能重複兌現或直接作廢。

只有兌現才異動銀行。登錄時轉應收票據 1105／應付票據 2010。每個事件保留日期、說明與操作者。票簿、自動領號、背書轉讓及解除票據連動尚未完成。

## 費用與期初帳款

先新增費用類別，再輸入未稅金額、稅額及事由，形成應付費用 2500，可部分付款。費用付款不能超過未付餘額，也不會自動分攤進銷貨成本。

期初帳款填應收／應付、對象、原未結金額、舊單號參考及到期日，可保留已逾期到期日；對應期初權益 3000，後續從該筆「沖帳」。避免同一餘額重複建立；目前尚無舊單號唯一性與自動批次映射。歷史期初預收預付須另設期初流程，不能使用「新增預收」虛構一筆實際銀行收入。

## 資料升級及回復

`src/migrations.mjs` 執行新增欄位、資料表與控制科目，不清除原表。舊付款維持原科目 1000，既有到期日不重算，既有帳號與密碼保持原值。v1 商品的新價級初值等於原標準售價，避免無意帶入零元。

公司與示範資料庫已於本次升級前線上備份於 `data/backups/`；旁邊 JSON 是副本驗證紀錄。`node scripts/pre-upgrade.mjs company` 可再產生線上備份並在拷貝驗證升級，檢查所有既有欄位／資料列的雜湊與子帳一致性；不輸出密碼或資料內容。

升級成功後不要直接用舊程式開啟新資料庫。回復時須停止服務，保存當前資料，再配對升級前備份與 v0.1 程式還原；升級後新交易必須先核對、重建或轉回。正式環境仍需專責人演練，不能把覆蓋資料檔當成日常還原按鈕。

## API 及驗證

新增：`GET /api/capabilities`、`GET /api/sales-price?partner_id=...&product_id=...`，與 `POST /api/contacts`、`/addresses`、`/departments`、`/employees`。財務 POST 在 `/api/finance/` 下：`accounts`、`transfers`、`batch-payments`、`payment-reversals`、`advances`、`applications`、`refunds`、`opening-items`、`opening-payments`、`bills`、`bill-events`、`expense-categories`、`expenses`、`expense-payments`、`allowances`。

所有變更沿用登入、CSRF、同來源、角色檢查、整筆交易及冪等請求。金額傳一般十進位字串，API 回傳金額仍為分整數。`GET /api/bootstrap` 按權限加入新主檔與財務資料；`GET /api/integrity` 新增預收預付、待退款、票據及費用子帳核對。

自動測試以獨立資料庫執行；瀏覽器驗證僅使用虛構示範資料。完整測試可執行 `verify.cmd`。外部發票回執、平台 API、真實印表機、長時間多人負載與公司財務驗收仍未完成。
