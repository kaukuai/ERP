# v0.3 操作與升級

更新：2026-11-02。這輪將 15 項驗收需求由待建／部分具備提升為可操作，另補強揀貨、盤點及成本重估。最新清單為 51 可操作、30 部分、20 待建、14 外部整合；尚未達全功能對等。項目權重不同，不能視為工程完成百分比。

## 新增作業入口

「進階作業中心」提供：批次揀貨、多單位、商品圖片、條碼標籤、成本重估、交易明細與排行、盤點匯入、銀行分行、票簿、直接進銷貨、單號規則及管理員流水重建。依角色顯示可用入口，伺服器仍獨立檢查權限。

## 商品單位及非庫存服務

- 商品編輯可選實體庫存或服務／非庫存品，並保存發票品名。服務可進報價、訂單及採購，但不預留或異動庫存；採購服務記營業費用，退回時回沖費用。
- 多單位可定義「1 箱 = 12 個」、該單位售價、採購參考價與條碼，比例最多三位小數。換算後仍須符合基本庫存最小精度 0.001，否則拒絕交易。
- 訂單明細各選商品與交易單位，數量及單價以該交易單位輸入。庫存、預留、調撥及盤點以基本單位保存；採購連動亦依基本量檢查，採購表單單價為基本單位採購價。
- 客戶專屬基本價依換算比例帶入；零售／批發／網路政策同樣按比例。一般政策使用單位設定價；最近價格只取相同交易單位及比例的核准單。
- 單據凍結單位名稱、比例、基本數量、商品性質及各列稅額。之後改單位設定不追改歷史交貨／退貨。已有交易的商品不能切換庫存類型或基本單位，請另建品號。
- 同一張單據同一商品維持一列；若同時以箱及個接單，請先換算成其中一種交易單位。這是目前明確邊界。

## 混合稅別及整單折扣

單頭稅別／稅率是預設值。各明細可另外選外加稅、含稅、免稅及自己的稅率；外加稅配零稅率與免稅保留不同類型。這是 ERP 金額計算功能，尚未完成正式電子發票整合。

整單價格折扣按各列原本含／未稅價格基礎比例分攤，各列稅額再重算。分攤及稅額以整數分及累計比例處理尾差；草稿預覽由伺服器計算，儲存、分批交貨與退貨使用凍結後金額。折扣不能超過商品合計，不能以修改小計繞過單價、數量及折數驗證。

黃單顯示明細稅別、整單價格折扣及總額；剩餘結案會保留原因與未交結案量。

## 直接進銷貨與剩餘結案

具核准及庫存權限者可從「直接進銷貨」一次建單、核准與出入庫立帳。不需要事先開單，但仍保留自動建立的可追溯來源。信用或庫存任一步不通過，整筆回滾，不留下半張單。

已核准／部分交貨單可「結束剩餘未交」，必填原因、檢查修訂號，保留原訂購量與實際已交量；未交轉為結案量，釋放銷售預留。結案不反轉已交交易及帳款，也不允許繼續交貨。作業中的揀貨單、未結束的連動採購須先處理。

## 批次揀貨與條碼核對

1. 選倉庫及多張已核准、尚未交完的同倉訂單。
2. 系統彙整實體商品，保留各來源與交易單位；同一來源不能同時放進兩張作業中的揀貨單。
3. 掃基本單位或箱／包條碼，依所掃條碼單位填數量，轉成基本數量依來源順序分配。
4. 不存在條碼、錯品、超量或重複掃描會阻擋。全部比對完成才能出貨。
5. 出貨逐來源產生出庫與應收，在同一資料庫交易執行；任一來源失效或不足則全部回滾。

取消揀貨會保留掃碼紀錄且不動庫存，可重新開單。服務不進實體揀貨單，請另行完成服務交貨。目前仍不支援缺貨訂單的部分配貨策略；一般訂單核准仍要求完整可用量。

## 圖片、標籤與盤點表

商品圖片接受 512 KB 以下 PNG、JPEG、WebP，檢查檔案內容標記，不接受 SVG；讀取需要登入。圖片可在圖片列表及選品明細顯示。

標籤支援 Code 128、EAN-13、QR Code，選商品或換算單位、張數、是否顯示售價、A4／A5／連續紙及標籤尺寸。先驗證再提供列印頁連結，避免彈出視窗封鎖。依寬度自動排欄；連續紙每張分頁。列印請使用 100% 比例並先核對紙張與掃描器。本次只驗證瀏覽器版面與軟體掃碼流程，尚未做實體掃描器／印表機驗收。

盤點可列印空白表或核對表。CSV 欄名為 `sku,actual_qty`，先預覽差異再儲存；未列入的商品保留原實盤數量。資料重複、超出盤點範圍或修訂失效會阻擋。儲存後仍需主管過帳，快照之後有異動仍不允許直接過帳。此入口不是 XLSX 匯入，也未完成分區盤點排程。

## 成本重估與報表

成本重估可指定新的總存貨價值或每基本單位成本，只改金額，不改數量與預留；依預覽數量及金額阻擋過期操作。零庫存或服務不能重估。差額透過存貨／調整損益入帳並留紀錄，尚無成本批次匯入。

交易報表可選銷貨／進貨、日期及客戶／廠商、商品、分類、業務、部門、年度月份分組，顯示排行及明細並匯出 CSV。按實際出入庫、退貨、折讓日期計列；整筆折讓依來源未退明細金額分配供分析。不同商品／單位不直接加總數量。員工可連結登入帳號，新單保存當時部門；舊單未保存分類／部門則列未分類，不猜歷史。

畫面最多 500 明細列，匯出含本次全部結果；原始交易數上限 10,000，超過須縮小範圍。報表尚未納入進銷費用成本分攤，毛利不是公司淨利，也不代替稅務申報。歷史庫存、交叉矩陣及自訂報表仍待建置。

## 銀行、票簿及單號

可維護銀行／分行代碼並連結資金帳戶。票簿設定銀行帳戶、前綴、起訖號及補零位數，單本最多 10,000 號，區間不能重疊。

登錄應付票據可選票簿，伺服器在同筆交易取下一可用號、分配帳款及登錄票據。空白票可指定號碼作廢，已開票則走票據作廢；作廢或已使用的號碼永不重用。系統目前採全域票號唯一規則，跨銀行如有相同票號，請使用可區分銀行的前綴。背書、轉讓與非帳款票據仍待開發。

管理員可依單據類型設定顯示前綴、分店碼、日／月／年／連續流水及補零位數；既有號碼不改。新號會跳過已用號碼，超過設定位數會阻擋，避免重複或截斷。分店碼只是編號，尚不代表已支援獨立分店帳套。

## 流水重建

僅管理員可預覽庫存與預留、應收付及期初帳款的來源差異。它重算帳面餘額，不重寫原單、收付款、退貨或傳票。

執行時必填原因，伺服器先線上備份至資料庫旁的 `backups/`，再確認來源及帳面快照沒有改變，於同一筆交易寫回並跑完整一致性檢查。若來源不合法、快照失效或與總帳不符，整批回滾。全部差異、原因與備份檔名留存操作稽核；不以補一筆平衡分錄掩蓋來源錯誤。

本次只在測試庫主動製造及修復差異。沒有對公司庫執行重建或測試交易。備份及還原方式需由公司維運負責人管理。

## 升級與驗證

資料庫升至 schema 3，新增欄位／資料表，不刪除既有交易。舊已核准單保留原計算流程，新建或重新編輯草稿採用新版逐列快照。舊單後續交貨與退貨仍能核對原金額；歷史報價轉單也保留原快照。

公司與示範庫升級前已線上備份，於副本逐表比對既有欄位雜湊並跑一致性檢查。備份為 `data/backups/*-before-v03-*.sqlite`，旁邊 JSON 記錄驗證結果。不應以舊版程式開啟新資料庫，回復須配對舊程式與升級前備份並核對之後交易。

執行 `verify.cmd` 或 `npm test`；`npm run check` 檢查所有新模組。條碼函式庫已隨程式附帶固定版本與授權，正常啟動不需安裝套件；詳見 [開源元件](../THIRD-PARTY-NOTICES.md)。
