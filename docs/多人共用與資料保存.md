# 多人共用與資料保存

同一公司可以建立多個獨立帳號，透過同一個 ERP 服務同時作業。使用者能看或修改哪些資料，仍依該公司的角色、人員上下階及資料範圍設定。寫入集中在公司的 SQLite 帳套；關閉瀏覽器、個別使用者登出或關閉服務，都不會清除正式資料。

同一張單據的修改有修訂檢查，別人的更新已先保存時，舊畫面會提示重新開啟，不會靜默覆蓋。庫存及會計採交易鎖，分批進出貨在取得寫入鎖後才讀取最新已交量。生成資料的 HTTP 測試已驗證 20 個獨立帳號同時登入、新增、衝突處理及服務重啟；這不是正式企業資料量的長時間負載驗收。

## 三種使用情境

| 使用方式 | 多人是否共用同一份資料 | 保存位置 |
| --- | --- | --- |
| 公司同仁連到同一個正式 ERP 網址 | 是，依帳套與權限存取 | 該服務主機的公司資料庫及備份 |
| 每台電腦各自下載本機包、各自執行 | 各自有資料，不會自動同步 | 各電腦的使用者資料位置 |
| Vercel 網頁展示 | 各分頁為獨立展示狀態 | 暫存且可能重置，不作正式資料保存 |

多公司使用不同資料庫、帳號、登入 Cookie 與 CSRF，跨公司不自動共用資料；授權的管理彙總亦須由各帳套管理員另外開啟。

## Windows 電腦作為公司的服務主機

預設 `start.cmd` 只供同一台電腦使用。若要讓其他電腦登入，選定一台持續開機的主機，將 HTTPS 網址指向該主機上的反向代理；大家使用這個網址，不各自開一份獨立帳套。

1. 先下載、解壓完整 Windows 程式包；第一次先以一般 `start.cmd` 在本機建立公司及管理員，再停止服務。未初始化的資料庫不能直接設定共用網址。既有使用者保留原資料位置及完整備份，關閉舊服務。
2. 準備公司控制的網域、有效的 HTTPS 憑證及反向代理。內網可使用公司憑證管理方式；外網則需相應的 DNS、網路與 HTTPS 設定。
3. 反向代理保留原 Host，轉送至 `127.0.0.1:4320`。例如相應代理設定為：

```text
erp.example.com {
    reverse_proxy 127.0.0.1:4320
}
```

4. 在 ERP 程式資料夾以命令提示字元啟動：

```bat
start.cmd --site https://erp.example.com
```

把範例網域替換成實際公司的網址。ERP 本身仍只監聽本機，由 HTTPS 代理提供其他電腦的連線；程式會設定精確允許的主機名稱及 Secure Cookie，不關閉來源／CSRF／帳號檢查。

共用網址會保存在原本機設定，之後雙擊 `start.cmd` 會沿用，更新程式資料夾也不會另建空帳套。要改回僅本機，先停止服務，再執行 `start.cmd --local-only`。修改共用網址或程式版本時，不會悄悄沿用舊的執行中服務。

管理員在該公司的「系統與資料管理」建立每位同仁的帳號及權限，將公司 HTTPS 網址提供給同仁。主機必須開機且 ERP 服務與代理正在運作；停止服務時其他人暫時無法連線，但磁碟資料仍在。

不要將多份同步磁碟或網路分享資料庫當成多人同步服務；所有使用者應經同一個服務寫入。備份需包含根庫、公司目錄、全部公司庫及備份清單，並保留另一個磁碟的副本。

## 正式雲端主機

也可使用具持久磁碟的 Node／容器主機，依 [雲端部署](雲端部署.md) 設定 HTTPS、資料目錄與備份。Vercel 可以作為正式主機的前台代理；單靠目前 Vercel 展示模式不會變成所有同仁共用的正式資料庫。

目前交付的是程式及安裝包。雲端工作環境無法直接設定使用者電腦的網域、憑證、反向代理或網路，不能據此推定公司共用網址已開通，或正式資料已移轉。
