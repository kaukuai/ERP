# 上線缺口與開發順序

v0.4 已新增多公司、合併進出貨、月結、對帳、批號、維修寄售租賃及 POS 本地流程，詳見 [操作與升級](v0.4操作與升級.md)。待建置數為 0 不表示全功能或正式上線完成；E08／X10 外部驗證、其他部分項目及外部整合仍需驗收。最新逐項差距與來源見 [數碼一號功能對標與驗收](數碼一號功能對標與驗收.md)。

更新：2026-11-02。目標為約 20 人使用的買賣型公司，倉庫及主檔自行新增，不擴充工廠自製流程。

## 目前交付的定位

已交付可持久化的核心系統、操作介面、黃單、交易檢核、移轉入口、測試及研究文件。核心可試行，但尚未達到可宣告全面取代公司舊 ERP 的程度。沒有串接或更動舊系統，也沒有把公司真實資料放入示範版。

## 20 人部署的容量驗收

已驗證 20 個獨立帳號同時建單、單號不重複、每位業務只看到本人單據。還沒有驗證長時間持續交易、實際公司歷史資料量、斷網重連、硬碟耗盡、服務重啟中斷、多台主機、高可用或備份期間尖峰流量。

建議以公司的典型日與尖峰日資料回放，量測：登入、商品查詢、客戶歷史、存單、核准、出入庫、沖帳、報表與備份的延遲、錯誤率、CPU／記憶體及交易鎖等待。驗收門檻應在測試前由公司約定，不能將本次單機測試時間直接當成承諾。

SQLite 適合作為此版單機試行核心。若資料量、寫入、報表或可用性要求超過合適範圍，安排 PostgreSQL 與資料存取層遷移，並重新跑所有一致性測試。

## 尚需公司的資料

- 實際商品／服務類型，是否有序號、保固、批號、效期或維修需求。
- 商品、客戶、廠商、倉庫匯出樣本及欄位說明。
- 各品／倉庫數量與成本，未交訂單／採購，應收付及已收付明細。
- 月結方式、收付款／退款、訂金、發票及稅額的實際案例。
- 20 位使用者的部門、角色、資料歸屬與主管核准範圍。
- 公司伺服器或主機管理方式、備份責任人與可接受中斷時間。

不需要提供管理員密碼、銀行密碼或電子發票正式金鑰給聊天；部署時由公司自行設定並放入受控的秘密管理方式。

## 轉換驗收條件

| 面向 | 驗收要求 |
| --- | --- |
| 基本資料 | 主檔代號唯一、停用與重複資料有處理紀錄 |
| 存貨 | 每品／倉庫數量、成本及借出入餘額與舊系統或核准盤點一致 |
| 單據 | 未交量、已交量及取消／終止狀態一致 |
| 帳款 | 客戶／廠商未結、已沖帳、預收預付與退款餘額一致 |
| 總帳 | 期初借貸平衡，存貨／應收／應付控制科目可對回子帳 |
| 權限 | 各角色完成正向／越權案例；離職停權與主管代理可執行 |
| 列印 | 真實品名、長備註、多頁與紙張／印表機實測 |
| 維運 | 備份可還原、故障回復可操作、服務與日誌有管理人 |

完整功能是長期版本與維運責任；本版的已做、待做及限制應持續維護，不使用「最完整」作為無法驗證的完成聲明。
